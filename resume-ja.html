No.4 メッセージアプリ｜iOS 版の立ち上げとモバイル開発リード モバイル開発リード / iOSSwift · AVFoundation · WCDB約8か月で初回リリース、会話一覧の更新時間を70%短縮

期間

2024年〜現在

チーム体制

モバイル4名（iOS 2名、Android 2名）。両プラットフォームのリリースを担当し、iOS の開発も兼任。

担当業務

  • ネイティブ iOS 版の技術選定、プロジェクト構築、主要機能の開発
  • 要件整理、担当の割り振り、日程調整。テスト、不具合修正、リリースの推進
  • 実装例とコードレビューによるモジュール境界の統一

技術的な取り組み

  • 設計：Swift のプロトコルと依存性注入で機能間の依存とアプリ固有の設定を分離し、複数アプリで使う共通 SDK を切り出し
  • 会話一覧：更新時間を70%短縮（アプリ実測）
    • 会話ごとのクエリを WCDB の一括取得に置き換え、初期表示の先読みと概要のキャッシュを追加
    • 会話1,000件の模擬データでの比較で、SQL クエリを3,000回から36回に削減
  • 暗号化動画：最初のフレーム表示を8.7秒から0.7秒に短縮（ローカル比較、16 Mbps 制限）
    • AVAssetResourceLoaderDelegate でプレーヤーが要求するバイト範囲を暗号化ブロックに対応付け、ダウンロードと並行して復号
    • 最初のフレームまでのダウンロード量を16.1 MB から1.1 MB に削減
  • 音声・ビデオ通話：Daily SDK で初期版の通話機能を一人で実装。システムの音声出力選択で受話口・スピーカー・AirPods の切り替え不具合を解消し、その後 CallKit を保守
  • 複数端末への着信：初期版のシグナリングを設計し、1台で応答するとほかの端末の着信が止まるよう Android・バックエンド担当と対応
  • 並行処理：TaskGroup で添付ファイルの同時アップロード数を制限し、actor で投稿状態を隔離
  • 開発基盤：CocoaPods から Swift Package Manager への移行を推進し、Xcode Cloud のタスク開始からアーカイブ成功までを40%短縮。メインアプリと7つのコンポーネントリポジトリに PR の自動チェックを整備

No.2 動画制作・投稿｜投稿システム、編集、コンポーネント化 シニア iOS エンジニア → チームリーダーObjective-C · Swift · AVFoundation投稿時間を50%短縮、4K 圧縮時のピークメモリを60%削減

期間

2019年3月〜2022年9月

チーム体制

動画制作領域の iOS チーム5〜6名（本人含む）。後期はチームリーダーを担当。

担当業務

  • 動画投稿システムと制作機能のコンポーネント化を担当し、編集機能の開発にも参加
  • 2か月ごとの技術計画を起案し、チーム内の分担とスケジュールを管理
  • 新人4名のメンターを務め、新卒2名を本採用まで支援

技術的な取り組み

  • 投稿の高速化：圧縮とアップロードを並行化し、通常の通信環境で投稿画面を開いてからアップロード完了までの時間を50%短縮
  • タスクの永続化：画面を離れた後も処理を継続し、アプリ再起動後にアップロードを再開
  • 4K 圧縮のメモリ：ピークメモリを60%削減
    • Instruments と編集 SDK のソースコードでメモリ不足の原因を特定し、端末のメモリ容量に応じて処理を切り替え
    • A/B 比較で効果を確認し、修正は SDK チームに採用
  • コンポーネント化：編集と投稿をホストとのブリッジとサンプルアプリで単独開発・デバッグ可能にし、ビルド済みコンポーネントで重複コンパイルを削減
  • 編集モデル：Action / Revert による Undo / Redo の共通モデルを設計し、チームで実装。後続の編集機能でも利用

期間

2017年7月〜2019年2月

技術的な取り組み

  • 弾幕コメント：プレーヤーの弾幕コメント機能を一人で設計・実装。速度差から追いつく時間を計算し、同じレーンでの重なりを防止

    • サイズ増加のチェックをマージフローに組み込み、しきい値を超える変更をブロック
